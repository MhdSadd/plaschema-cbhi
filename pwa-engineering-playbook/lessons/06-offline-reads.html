Reference data · about 15 minutes

Make reads honest offline

Offline data needs a provenance: who it belongs to, when it was downloaded, which access rules produced it, and when it becomes too old to trust.

Define the offline-read contract

For each dataset, record:

  • The owner user, tenant, or public scope.
  • The server revision or download time.
  • The access signature used to filter it.
  • The maximum useful age.
  • Whether stale data is still usable or must block the task.
  • How the complete dataset is replaced.
  • What the screen shows before the first download.

A freshness duration is a product rule, not a generic cache value. A safety checklist may require the latest version. A list of villages may remain useful for days. A price may be wrong after minutes.

Download, validate, then replace

Do not delete the old dataset before the new download completes. If the request fails halfway, the old complete data remains more useful than an empty or partial cache. For large collections, NDJSON or another streaming format lets the client parse one record per line rather than holding a huge JSON array.

const needsRefresh =
  !metadata ||
  metadata.accessSignature !== currentAccessSignature ||
  Date.now() - Date.parse(metadata.syncedAt) > maxAgeMs

if (needsRefresh) {
  const rows = await downloadAndValidate()
  await db.transaction('rw', db.references, db.metadata, async () => {
    await db.references.where('ownerId').equals(ownerId).delete()
    await db.references.bulkPut(scopeRows(rows, currentAccess))
    await db.metadata.put({ ownerId, syncedAt: nowIso, accessSignature })
  })
}

Access changes are invalidation events

If a worker moves from Ward A to Ward B, age alone is not enough. Compare a stable signature of the current authorized IDs with the signature stored during the last complete download. Refresh when it changes. Hide unauthorized cached rows immediately, even if refresh cannot yet complete.

Local filtering is not authorizationIt reduces accidental display and supports offline UX. The server must still authorize every later mutation because the device can be modified and permissions may have changed.

Tell the truth in the interface

Knowledge check

Why store an access signature next to the download time?

A fresh timestamp only says when data was downloaded. The signature says which assignments or permissions produced it. A changed signature requires invalidation even when the data is only minutes old.
